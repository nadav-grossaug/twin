# Process log: real-vs-fake classifier track

## Phases and decisions (started 2026-11-02)

- **D1 (scope): shared core plus per-dataset implementation.** `src/realfake/` holds the dataset-independent parts (split, models, metrics, controls, importance, report); each dataset supplies a sampler and a featurizer. SNAP first. Eval-only: lives in the inside-only eval zone, imported by nothing in inside, transfer or outside.
- **D2 (sample): random-walk subgraph of random size**, label = real or synthetic source graph; ids, ordering and column order dropped. See `docs/realfake/snap.md`.
- **D3 (honesty): every result is reported with controls**: real-vs-real, permuted labels, held-out fake seed, bootstrap CI, baselines for scale. See `docs/realfake/PLAN.md` section 4.
- **D4 (implementation, 2026-11-02): all five plan steps done on branch `realfake`.** Core `src/realfake/` (dataset, split, models, metrics, controls, importance, report; numpy logreg + sklearn gradient boosting with uniform log-odds `scores`), SNAP `src/graph_aim/eval/discriminator.py` (walk sampler + featurizer), stage-3 CLI `snap/eval/discriminate.py`, tests `tests/realfake/` + `tests/graph_aim/eval/test_discriminator.py` + `test_discriminate.py`, boundary test extended to forbid `realfake` outside eval. Built by three subagents (core, SNAP featurizer, CLI+run), each integrated and re-tested by the orchestrator; full suite green.
- **D5 (fold design): one dataset per method, folds rotate the held-out fake seed.** A method = a variant with its 3 generation seeds as fake sources; fold `s` holds seed `s` out for test, real rows are group-split by start node. A single-fake-source method falls back to a stratified group split.
- **D6 (first SNAP result): every graph_aim variant is near-perfectly detectable at walk level; the epsilon gradient lives in the attribute importance.** Controls clean (real-vs-real 0.515/0.528 logreg/gbm, permuted ~0.5, ER and Chung-Lu at 1.0000). Gradient boosting reaches AUC 0.9994-0.9999 for every variant, eps 0.5 through inf and nocap_nonprivate alike; logreg alone 0.993-0.997. Permutation importance: the attributes group dominates everywhere and falls monotonically with privacy budget (auc_drop 0.43 at eps 0.5 -> 0.24 at inf); degree second (0.001-0.043), structure and size negligible. AUC >= 0.995 in every walk-size bucket. This is a fidelity finding the scalar metrics and the 0.99-everywhere link-prediction utility (D12 in `docs/snap/PROCESS.md`) hid; it is not a privacy statement. Results: `snap/eval/results/discriminator*.csv`, notebook `snap/eval/notebooks/viz_discriminator.ipynb`, report `snap/reports/discriminator_v1.md`.

- **D7 (v1.1 rerun, 2026-11-02): the attribute-coupling generator revision does not move the discriminator; the giveaway is per-walk attribute composition, and the none/other artifact suspicion is refuted.** Identical pipeline rerun on the v1.1 graphs of branch `aim-coupling` (pinned `e802ff70`; package D: three homophily `attr_edge_pair` groups + multi-channel rewiring, attr_degree 0.35/4 bins): gbm AUC still 0.996-0.9999 at every epsilon, attributes-group importance unchanged (0.43 -> 0.23 across eps vs 0.43 -> 0.24 in v1). Splitting the attributes group (new diagnostics in `snap/eval/results_v1_1/discriminator_importance_{perfeature,subgroups}_epsinf.csv`): no single feature exceeds auc_drop 0.0012 (the signal is a distributed fingerprint), by statistic type the per-walk value shares dominate what is attributable (`type:share` 0.09-0.10; `none_other` 7e-5 v1 / 2e-5 v1.1, artifact refuted; `same_edge_rate` ~0; `pair_edge_match` ~0.003), and hometown is the strongest single column (0.0164 -> 0.0075, the one visible v1.1 improvement). Reading: real walks see locally concentrated attribute values (communities share hometown/locale); matching global homophily edge-count tables, even three of them, does not create that local coherence. Implication for the generator: attributes need community/cluster-level coherent placement. Results `snap/eval/results_v1_1/`, notebook `snap/eval/notebooks/viz_discriminator_v1_1.ipynb`.

- **D8 (GeoLife design, 2026-11-03): sample = a contiguous window of k GPS points of one user, k log-uniform on 30..600 (capped at the user's longest run), never crossing a trajectory boundary or a > 2 h gap; group_id = uid.** Dropped by construction: user and trajectory ids, absolute timestamps and dates (real GeoLife is 2007-2012, synthetic epochs 2024 — a date feature would separate perfectly), absolute lon/lat (all geometry from steps / centered coordinates via the fixed-origin `to_xy` projection, so features are translation-invariant), per-user point volume (uniform-over-users sampling plus the group split). The map group (distance to public places, on-road H3 cell shares) is kept separate because it alone reads absolute coordinates: it captures a real documented gap (93% of synthetic stops snap to a place vs 55% real, `m-v2.md` section 6 / B7) but is partly different by construction, so it is toggleable (`--no-map`) and the headline AUC is reported with and without it. One fake source (`outings_v2_seed0`) means D5's single-source fallback applies: stratified group-split folds over 3 fold seeds; held-out-source folds reactivate if a variant ships several seeds. No realfake core changes; new code only `src/geolife/eval/discriminator.py`, `src/geolife/eval/discriminate.py` and the stage script `geolife/eval/discriminate.py`. Design and feature table: `docs/realfake/geolife.md`. Results pending (first full run not yet done).

- **D9 (first GeoLife result, 2026-11-03): the synthetic Beijing traces are near-perfectly detectable at window level, and the giveaway is the per-step texture, not the map.** Controls clean (real-vs-real 0.47-0.53, permuted 0.46-0.49). gbm AUC 0.9996 with the map group and 0.9995 without it (logreg 0.983/0.981); AUC 0.997+ already at k 30-60 points. Grouped importance: `sampling` 0.26, `kinematics` 0.06, everything else <= 0.0002 — the map group separates alone (`place_dist` single AUC 0.70) but the model never needs it. Per-feature (notebook): synthetic traces are too SLOW and too uniform in the upper speed/step tail (`thin30_speed_q90` 4.0 real vs 1.0 m/s synthetic; the overcorrection of the old 2.7x-too-fast baseline — seed0's `sensor_speed` fell back at signal 1.9 < 3.0), and the dt texture is wrong in a specific way: real loggers LOCK on one interval (flat runs of identical dt, modal share p50 0.84, repeat probability up to 0.95, long-pause tail p99 ~137 s) while rendered dt flickers step to step inside a narrow band (modal share 0.55, repeat 0.28-0.67, p99 ~26 s) — `dt_mode_share` per-feature drop 0.111, the only material one; signal otherwise redundant, the SNAP pattern. Generator implications: per-mode speed scale and spread, dt as a locked/regime process with a heavy pause tail (not per-step draws), map gap deprioritised. Results `geolife/eval/results/discriminator{,_nomap}/`, notebook `geolife/eval/notebooks/viz_discriminator.ipynb`, write-up `docs/realfake/geolife.md` section 5.

- **D10 (GeoLife dt-texture round, 2026-11-03): fix the dt giveaway through the artifact, not the generator's constants (user decision); the dt texture now matches, the headline barely moves.** Two new DP sensor tables (geolife PLAN step 9): `sensor_dt_runlen` (pmf of maximal equal-rounded-dt run lengths) and `sensor_dt_runlen_user` (one-hot of the user's MEAN run length), same caps/noise/ledger machinery; usable on all 3 dev seeds (28 tables, eps 6.000). Renderer: per-user home interval held for geometric runs (mean 2m-1) with single-step excursions, so window repeat = 1 - 1/m from the released table; per-run pooled draws and the old per-step draw remain as fallbacks. Iterations, each measured on the Beijing set: pooled pmf over-locks (window repeat 1.00), per-user median under-locks (0.65), per-user mean matches repeat (0.83) but not modal share (0.51), home+excursion matches both (0.84-0.85 / 0.92 vs real 0.836 / 0.84). Discriminator: gbm 0.9996 -> 0.9970 (map and no-map alike), logreg 0.983 -> 0.942 (0.930 no-map), sampling drop 0.26 -> 0.20-0.23, kinematics 0.06 -> 0.11-0.12; controls unchanged. Reading: the linear signal fell clearly, the boosted model still finds a redundant residual; best single separators are now all kinematics (seed0 `sensor_speed` fails its floor, so speeds render from defaults: too slow, too uniform). Next GeoLife item: the speed regime through the artifact, then the base interval (2 s vs 3 s) and the within-window pause tail. Results replaced in place (first-run tables in git history, `97571a4`); write-up `docs/realfake/geolife.md` section 6.

- **D11 (GeoLife without speed and distance, 2026-11-03): speed and distance are out of scope for this data's model (user decision), so they are removed from the classifier, not fixed in the generator.** Mechanism: `FeatureSubset` (column selection on top of the unchanged `TraceFeaturizer`, groups left empty are dropped) with the preset `SPEED_DISTANCE_FEATURES` (`discriminate.py --no-speed-distance`; `--exclude` takes extra fnmatch patterns). Dropped: step length, speed, acceleration (raw and 30 s), reversals per km, slow-point shares, stop jitter in metres, map distances to places (24 features, 29 with map). Result on the D10 synthetic set: gbm 0.990, logreg 0.892, controls clean; sampling carries the separation (group drop 0.36: `dt_mode_share` 0.166, `dt_le2_share` 0.065, `dt_log_std` best single AUC 0.71, no in-window pauses), heading second (0.066). The earlier all-feature results stay as committed; new tables in `geolife/eval/results/discriminator_nospeed{,_nomap}/`. Write-up `docs/realfake/geolife.md` section 7.

Status: implemented and run on SNAP v1, the `aim-coupling` v1.1 graphs, and GeoLife `outings_v2_seed0` (first run, dt round, and without speed/distance; all on `aim`).
